# 룸노트 테스트 사이트

작업실 배치도와 장비를 관리하는 GitHub Pages 사이트입니다. 화면은 GitHub Pages에서 제공하고, 계정·공용 기록·방별 편집 잠금은 Supabase에 저장합니다.

- 방 배치도: 1~11번 방, 1·2번 가공실, 블리스터, 공급실.
- 건조기/섞는 기계 현황 전환, 드래그 이동, 두 손가락·마우스 휠 확대.
- 이용 품목과 시작 시간, 예약, 주사기 제작 준비 제품·수량·상태.
- ID별 메모 추가·삭제, 수정·취소·적용.
- 이메일 없는 아이디·비밀번호 로그인. 가입 시 사이트 표시 이름을 지정하며 한국어도 가능합니다.
- 테스트 계정은 가입 즉시 사용 가능합니다. 비밀번호는 bcrypt 해시, 세션 토큰은 SHA-256 해시로 서버에 보관합니다.
- 같은 방은 한 작업자만 편집, 다른 방은 동시에 편집 가능. 같은 계정의 다른 탭도 별도 편집자로 취급.
- 배치도에 `ID 수정중` 표시, 방별 수정 시작·종료·저장 기록.
- 20초마다 편집 권한 갱신, 연결이 끊기면 마지막 갱신 후 90초 이내 자동 해제.
- 저장 시 서버가 편집 권한·기록 버전·작성자를 검증합니다. 연결 오류나 잠금 만료 시 입력 내용은 화면에 남기고 저장을 제한합니다.

공용 서버 연결 후에는 변경 내용을 Supabase에 저장하고 다른 사용자에게 공유합니다. 로그인 세션은 해당 탭의 sessionStorage에 보관하며 비밀번호는 사이트 코드나 저장소에 보관하지 않습니다. 프로젝트 URL과 publishable key만 공개 파일에 포함합니다.

## 테스트 계정 사용

1. 기존 서버에는 `supabase/email_free_upgrade.sql`을 실행합니다. 방 기록은 유지하고 이메일 없는 계정 기능을 추가합니다.
2. 사이트의 계정 생성에서 아이디·표시 이름·비밀번호를 입력합니다. 이메일 확인과 관리자 승인은 필요 없습니다.
3. 아이디·비밀번호로 로그인합니다. 새로 가입하면 바로 로그인됩니다.
4. 표시 이름은 한국어를 포함하여 1~20자, 아이디는 소문자로 시작하는 3~16자의 영문 소문자·숫자·밑줄, 가입 비밀번호는 8~128자입니다.
5. 기존 이메일 방식 계정의 비밀번호를 옮기지는 않습니다. 새 테스트 계정을 생성해 주세요.

로그인 5회 실패 시 해당 아이디는 5분간 로그인을 제한합니다. 세션은 12시간 동안 유효하며 로그아웃하면 서버에서 폐기됩니다. 같은 방의 편집자·작성자 표시는 `표시 이름 (아이디)` 형식입니다. 화면 갱신은 활성 탭에서 약 5초 간격이며 서버가 저장 권한을 매번 확인합니다. 공개 가입이 가능한 공용 테스트 환경입니다.

## GitHub Pages로 공개

1. 공개 저장소 `roomnote-demo`를 만듭니다.
2. 이 폴더의 `index.html`을 저장소 최상위에 업로드합니다. README.md와 .nojekyll도 함께 올릴 수 있습니다.
3. 저장소 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**, **main**, **/(root)**를 선택하고 Save 합니다.
4. 배포 완료 후 Pages에 표시되는 주소로 접속합니다. 실제 주소가 확인되기 전에는 공개 완료로 간주하지 마세요.

`index.html`은 필요한 화면·코드·아이콘을 포함한 단일 파일입니다. PC 또는 휴대폰에서 같은 파일을 사용합니다. Python/Android SDK/APK/서명 키/로컬 기록 파일은 공개할 필요가 없습니다.

## 로컬 업데이트

기존 프로젝트의 모바일 체험 화면에서 공개 파일을 재생성합니다.

```powershell
py -3.12 D:/cod/roomnote-pages/build_site.py
```

생성된 index.html을 GitHub에 다시 반영하면 됩니다.
